# Decomposition: Hybrid Genetic Algorithm + Gradient-Based NLP

To address the "Curse of Dimensionality" in expanded search spaces (e.g., 0–16 reactors, 0–1000 batteries), we abandon exhaustive iteration in favor of a **Hybrid Evolutionary Strategy**.

Our architecture decomposes the problem into three layers:
1.  **Phase 0: Grid Seeding (Heuristic):** We perform a rapid, coarse scan of the landscape to identify high-potential "valleys." This seeds the initial population with viable solutions, preventing wasted compute on random guesses.
2.  **Phase 1: Genetic Algorithm (Global Search):** We treat hardware counts as "genes." Through **Selection, Crossover, and Adaptive Mutation**, the algorithm statistically converges on the global optimum by sampling <5% of the total search space.
3.  **Inner Loop (Fitness Function):** For every candidate generated by the GA, we run the **SLSQP** continuous solver to determine the maximum theoretical profit (fitness) of that specific hardware configuration.

## Log of Decisions

1.  **Switch to Probabilistic Search:** With the search space expanded by 10x, a brute-force grid search became computationally prohibitive. The GA allows us to navigate a massive universe of configurations efficiently.

2.  **The "Solver as Fitness" Proxy:** We do not estimate fitness. We rigorously solve the daily dispatch problem (using SLSQP) for every genetic candidate. This ensures the evolution is driven by physics-compliant economic data, not heuristics.

3.  **Multi-Start Solver Logic:** The non-linear efficiency curves ($Efficiency \propto Power^2$) created local minima where the solver refused to charge the battery. We implemented a **Multi-Start** approach: we solve every candidate twice (once with a "Demand-Following" guess, once with a "Flat" guess) and return the superior result.

4.  **Adaptive Mutation:** To prevent the population from converging too early on a sub-optimal hill, we added "Earthquake" logic: if profit stagnates for 8 generations, mutation rates spike from 15% to 60%, forcing the algorithm to explore new regions.

## Key Differences: Grid Search vs. Genetic Algorithm

| Feature | **Grid Search** (Code 2) | **Genetic Algorithm** (Code 1) |
| :--- | :--- | :--- |
| **Philosophy** | **Exhaustive.** Checks every single combination within a small box. | **Evolutionary.** "Hunts" for the optimum across a massive universe. |
| **Guarantee** | **100% Global Optimality** (within bounds). | **Statistical Confidence.** High probability of finding the global optimum. |
| **Scalability** | **Linear/Poor.** Doubling bounds doubles compute time. | **Excellent.** Can handle huge bounds (0-2000 units) with minimal cost. |
| **Precision** | **Fixed.** Defined by step size (e.g., "Step 1"). | **Adaptive.** Zooms in naturally, but requires a final "Neighborhood Polish" to fix integer errors. |
